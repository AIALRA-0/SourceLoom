# 生产部署

## 1 运行边界

单用户服务，后端只监听本机地址，公开入口由反向代理完成 HTTPS 和登录认证

`auth_mode=proxy` 同时核对回环来源、受信认证标记与指定用户身份，反向代理必须覆盖外部传入的身份头

模板中的目录是通用示例，生产实例的真实配置、账号、密钥、备份和回滚记录放在 Git 之外

## 2 安装与启动

使用 Python 3.11 或以上版本，在独立虚拟环境中安装仓库，复制中文写作技能的完整目录，设置 `SOURCELOOM_CONFIG` 与 `SOURCELOOM_DATA`

配置字段见 [运行配置示例](../config.example.json)，API 密钥不写进网页或仓库

网页服务使用 [网页服务模板](sourceloom.service)，后台执行使用 [后台服务模板](sourceloom-worker.service)，两者必须指向同一配置、材料目录与程序版本

网页进程只保存和展示任务，后台进程逐步执行，二者分别启动后验证页面关闭与服务重启的恢复行为

配置实际路径后启动，先验证回环健康检查，再连接已有认证代理并配置域名与证书

## 3 更新与回滚

每次发布保留一个带时间标识的程序目录，停机前备份 SQLite 数据库、全部资源与配置，切换程序路径后重新启动

验证健康检查、未登录拒绝访问、已登录材料列表、样本上传和候选下载，再确认其他服务仍正常

失败时恢复上一程序路径与原配置，保留新产生的材料目录供排查；数据库格式发生不兼容变化时必须使用匹配备份

## 4 容量与预算

单文件 25 MB，单次总量 100 MB，PDF 最多 50 页，解析进程等待上限 75 秒

Linux 解析进程另有 60 秒 CPU 与 768 MB 地址空间限制，服务整体内存上限由 systemd 限制

自动生产每篇最多 24 次调用、900 秒和两轮局部修复，单个任务的角色顺序执行，全站最多两份材料同时执行

每次普通调用最多 180 秒，专门配置的独立对话最多 360 秒，同时受本篇剩余时间限制；超时和未知结果不自动重发

已知响应可直接重新校验，未确定的远程调用仅查询原身份，恢复任务不重置原时间与费用记录

订阅渠道的输出参数不等于供应商的硬费用限制，必须结合实际用量、调用次数与等待期限判断成本
