# 完整写作技能怎样进入自动生产

## 1 实际交付范围

每次创建生产任务，系统复制配置所指向的完整技能目录，并保存文件清单与内容摘要，后续任务使用这个冻结版本

复制范围包含入口、规则、排版脚本、检查脚本、补丁工具及其他包内资源，排除版本控制目录、缓存与本地运行目录，不以几条摘录替代技能

从入口递归追踪所有本地规则文档引用，包括公式、结构排版、局部检查和开发原则等条件文档，逐文件全文加入每个角色的实际提示词

本轮实际版本有 342 个包内文件，其中入口及其引用的 8 份有效指令文档共 64,969 个原始字节，均完整交付；测试数据与历史档案作为包内文件保留，不把其中的旧命令提升为当前写作指令

## 2 模型怎样读取

- 有本地文件工具的执行通道，收到冻结目录位置和读取要求，同时仍收到全部规则正文
- 没有文件工具的接口通道，收到全部规则正文，记录为全文内联
- 运行环境拒绝文件读取时保留拒绝事实，不绕过权限，也不把模型自称读过当作访问记录
- 请求超过通道限制时停止或修正通道，不裁掉技能，也不截断原文

每次请求保存实际提示词、传输请求、原始响应、规则版本和通道用量，私有配置中的秘密不进入公开文档

## 3 如何约束正式输出

信息清点、清点审核、教学规划、规划审核、写作、写作审核、原文对照与局部修复分别执行

生成前逐项记录源信息、人称、指代、数量、条件、否定及原对象；写作后先用完整技能检查正文，再由独立角色对照完整原文与最终正文

正式结果要求机械发现均已处理、适用规则无已知违规或未裁决项、原信息逐项有对应位置、两个审核对应同一版本；未完成核对的正文仍可阅读和下载，但明确保留草稿状态

完整交付规则证明的是模型收到什么，不能证明模型必然理解或遵守，实际结果仍按 [真实试验记录](../reports/AUTOMATIC_TRIAL.md) 验收
