# SourceLoom 执行 Agent 的工程回报规范

## 适用范围与权威

本规则约束执行 Agent 的阶段更新、验收回报和最终工程交付，不是文章写作规范，不进入内容模型的 Prompt、模型任务包、论文正文、格式检查器或外部 Skill

正式报告采用当前适用 APCF 的十区块合同，并按 [APCF 工程回报适配](APCF_REPORTING_ADAPTER.md) 落实用户最新更正；该适配只负责本项目工程回报，不修改共享 Core Canonical Rules，不把没有运行过的原生 Gate 或 Finalize 写成通过

阶段更新可以简短，但最终报告不能用简报代替当前完整执行合同和验收结果；用户当前明确指定其他输出形式时，以当前用户要求为准

## 正式交付

最终报告依次包含：0. 精确状态头、1. 承上启下、2. 术语表、3. 执行清单、4. 验收记录、5. 完整讲解、6. 关键要点、7. 用户需要执行、8. 需要继续讨论、搜索或决策、9. 下一步推荐

状态头说明本轮真实版本、入口、当前清单与验收状态、阻塞和证据；未建立的原生 IT/TR 明确标为未建立，不自行编造框架身份

承上启下用 2–4 个短自然段交代已有状态、本轮问题、实际改变与当前落点，不用短标签或箭头代替叙述

执行清单是开始工作前的目标合同，不是完成后的改动摘要；验收是用实际证据判断这些目标是否成立，不是为了把已做动作包装成成功

术语表只解释报告实际用到且读者需要理解的术语，名称按真实来源核对，定义足以帮助读者理解后文；关键要点覆盖完整讲解的全部宏观结论、重要原因、实际结果、限制与剩余项，条数由内容决定，不固定为四条

同一最终报告保存在当前 TURN.md，CURRENT.md 从该报告派生；最终聊天正文不另写一套缩略结论，敏感证据仍留在本地，不因提供报告链接而公开

## BP 与五步验收如何使用

BP 使用描述性粗体标题，正文用完整语句说明动作、原因、结果或边界；比喻只帮助理解，不能替代事实或淡化风险，不要求每条使用相同长度或固定数量

五步验收放入完整讲解，用于检查本轮用户路径覆盖，不再成为另一套互相竞争的报告模板

- 功能验收说明从哪个真实入口操作了哪条核心功能，未执行就直接说明
- 结果验收说明实际产物是否满足事前判据，正文保护、图表归属和保存读回分别核对，不能用没有报错替代
- 异常验收说明实际错误、重复、缺失及保护行为，隔离故障与真实外部故障分开
- 连续验收说明同一构建实际运行的路径、输入类型与结果，回放不是新模型任务，单元测试不是文章数量
- 完成判定说明通过、部分通过或未通过的范围，部署、推送、用户数据变化、费用和剩余项分别明确

## 收口前复读

收口前重新读取 AGENTS.md、本规范和适配文档，再对照当前 CHECKLIST.md、TEST.md 与正式报告逐项检查：每个目标保留触发条件、原因、要求和判据；每个报告验收保留版本、操作、预期、实际与证据；术语没有虚构全称；关键要点没有遗漏重要结论；未执行项和真实剩余工作没有因简化被隐藏

机器解析通过只能证明它检查过的结构，不能证明自然语句、因果、定义充实度或总结覆盖全部合格；发现偏离时由当前执行 Agent 直接改正工程报告，不新增 Reviewer、模型请求或业务门禁
