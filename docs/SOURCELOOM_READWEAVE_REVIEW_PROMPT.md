请作为 SourceLoom 的独立架构和成品质量评审员，评估下面的迁移方案，并给出能够直接指导实现的修订稿

你的任务是帮助 SourceLoom 吸收 ReadWeave 已验证的低成本模型通道、证据检索、格式与风格约束以及测试闭环，同时保留 SourceLoom 的产品边界

## 1. 已确认事实

1. 夸父社 DeepSeek V4.1 Flash 专线按 0.15 倍率提供服务
2. 夸父社页面已经给出折后实付单价，每百万 Token 的未命中缓存输入为 0.225 美元，输出为 0.675 美元，缓存读取为 0.0075 美元

8. ReadWeave 的历史测试证明搜索本身不是主要费用来源，较大的浪费来自重复规划、协议恢复、全文审核和格式调用

## 2. SourceLoom 的产品边界

SourceLoom 处理用户上传的网页、Markdown、PDF、DOCX、纯文本、代码、表格、公式、图片、链接和其他常见文档对象

SourceLoom 的主要任务是：

1. 保留原文全部有效信息和对象
2. 在不改变主旨、作者立场、人称、指代、条件、否定、数字和不确定性的前提下重新组织表达
3. 改善段落衔接、解释顺序、术语定义、层级关系和阅读流畅度
4. 只做理解原文所需的最小解释和用户明确要求的受限扩充
5. 将最终结果转换为可以导入 ReadWeave 的内容包

SourceLoom 不是开放问题回答系统，也不是自动课程生成器

除非原文本身具有教学目的，否则不得自行加入课堂情境、虚构案例、练习、知识扩展或新的文章主线

## 3. 完整写作约束

所有影响正文的模型角色必须访问当前完整安装的 `human-readable-technical-writing` 技能文件，不得使用人工摘录的简版规则代替完整技能

固定优先级为：

```text
完整 human-readable-technical-writing 硬规则
> SourceLoom 原文保真与改写合同
> ReadWeave 中文风格基准
> 模型默认写作习惯
```

硬规则至少覆盖：

- 首次正式术语的中英文对应
- 缩写及名称内部缩写展开
- 标题使用 `1.`、`1.1.`、`1.1.1.` 层级
- 图表、按钮、内容型链接和标签解释
- 代码、公式、链接、引用和原始资源保护
- 图片、表格和嵌套容器中的实际居中
- 中文标点、空格、列表和平行结构
- 讲解从读者已有信息自然过渡到新信息
- 不用模板化定义或项目符号代替连续讲解

风格层只统一语气、句式、节奏、信息密度、段落中心、衔接方式和术语一致性，不得改变事实或增加新主题

## 4. 精简检索原则

SourceLoom 默认不搜索

只有存在可以明确定位的来源义务时才允许读取或搜索，例如：

- 原文给出 URL、脚注、论文、规范或内容型链接，改写需要解释其实际内容
- 正式英文名称、缩写全称、专名或指代无法从原文可靠确定
- 原文中的当前版本、价格、政策或状态需要按用户要求更新
- 图片、图表或页面结构包含理解原文所必需的信息
- 用户明确要求在原文基础上补充某一限定范围的外部资料

以下情况不得触发搜索：

- 只是改善措辞、层级、段落衔接或格式
- 原文已经提供充分事实
- 只是为了让内容显得更丰富或更专业
- 只是为了增加案例、历史、词源或旁支知识
- 只是为了通过格式或风格审核

有 URL 时直接读取目标页面，不先执行通用搜索

没有 URL 时按以下顺序执行：

1. 官方页面、原始发布者或免费结构化来源
2. TinyFish
3. Octen
4. Parallel，仅在需要独立交叉来源或前序失败时使用
5. 学术、人物或其他专项来源只在来源义务确实属于该类型时启用

搜索结果只能进入候选资源目录，不能直接进入正文

只有被改写计划明确选择、已经打开正文并绑定到具体来源义务的证据，才能交给写作模型

搜索结果不能扩大文章主旨，也不能把新的背景事实升级成原作者的主张

建议默认上限为：

- 每个来源缺口一次定向查询
- 每次最多检查三个候选
- 默认打开一个主来源
- 高风险或相互冲突的事实最多增加一个独立来源
- 两轮仍无法闭合时标记为未解决，不允许模型猜测

请评估这些上限是否恰当，并提出更好的统一规则，避免针对某个测试案例写特例

## 5. 建议生产流程

```text
原件冻结与对象清点
→ 改写合同与来源义务
→ 判断是否存在明确证据缺口
→ 必要时定向读取或搜索
→ 证据选择与来源绑定
→ 文章结构和段落衔接规划
→ 使用完整技能和选定证据生成正文
→ 确定性格式规范化
→ 格式与风格问题局部补丁，最多两轮
→ 数字、公式、代码、链接、引用、否定、条件、人称和来源保真检查
→ 最终网页与 ReadWeave 内容包
```

请重点评估如何减少 SourceLoom 当前重复的全量审核、教学复核、重新规划和整段重写，同时确保删除这些调用不会降低成品质量

## 6. 格式与风格复用目标

请评估应直接复用 ReadWeave 代码、抽取共享包，还是在 SourceLoom 中按同一契约重建以下能力：

1. 完整写作技能装载和版本指纹
2. `readweave-zh-technical-explainer-v18` 风格策略
3. 标题、列表、术语、公式、代码、链接和重复结构的确定性检查
4. 精确定位、不重叠的局部补丁
5. 数字、公式、代码、链接、引用、否定和限定条件保护
6. 最多两轮局部修复
7. 修复失败后保留完整正文和残留问题

禁止使用无条件的全文风格重写，因为它容易引入事实漂移、重复和结构膨胀

## 7. 夸父社和成本系统

夸父社应作为 SourceLoom 的低成本主模型通道，DeepSeek 官方或其他已验证线路作为备用

请评估以下设计：

- 调用前预留，调用后结算
- usage 缺失时保留未结费用，不写成零元

- 模型、搜索、页面读取和图片识别分别记录费用
- 恢复任务时不重复购买已经完成的阶段

请指出 0.15 倍率和已经折后的固定单价应怎样同时展示，避免重复打折或与其他官方模型价格错误比较

## 8. 低成本测试闭环

禁止对已经用模型生成过的旧材料再次付费生成

旧材料只能用于离线重放检查器、格式器、保真门和报告逻辑

真实测试必须使用新的现实材料，并保存完整输入和最终输出

建议测试分层为：

1. L0 确定性单元测试，覆盖格式、保护对象、成本、状态和幂等性
2. L1 冻结模型响应和搜索包的离线流程重放
3. L2 变体测试，移动段落、公式、代码、图片、表格和来源位置
4. L3 少量全新真实材料的完整夸父社生产测试
5. L4 用户在真实文章现场体验最终网页和导出结果

第一批真实材料建议包含网页、Markdown、普通 PDF、图片密集 PDF、DOCX、代码文档、公式文档和含内容型链接的文章

每份材料只生成一次，避免为了调参反复付费和过拟合

每轮记录：

- 最终成品是否可接受
- 原文对象覆盖率
- 数字、公式、代码、链接、引用、否定、条件、人称和指代保真
- 搜索查询、页面读取和图片识别次数
- 模型调用次数和各阶段调用分布
- 缓存输入、普通输入和输出 Token
- 本地估算、费用上界、未结费用和平台实际扣费
- 总耗时、失败、重试和局部补丁次数
- 格式问题、风格问题和内容问题分别统计

失败样本必须保留为固定回归，不得删除难例、降低标准或用新增简单样本稀释失败

小批量零失败只能证明本轮没有发现问题，不能声称总体不可接受率低于 1%
