# 需求对照与验收责任

## 1 记录原则

两份原始附件、本次用户原始消息与后续补充均保存在本机私有原件目录，摘要清单用于核对文件字节

这里记录可以公开的需求与实现对应关系，原始材料是方向核对依据，不能用这份提炼后的表代替原文

“已实现”说明对应程序或文档存在，不等于所有真实材料都已经通过验收；“待验收”与“待实现”必须分别记录

## 3 后续顺序

先解决冻结后补漏与分层长文处理，再接入视觉核对和受限研究获取，然后完成真实 ReadWeave 编辑器往返

质量对照使用独立来源与留出材料，只有前一批证明改进有效才扩大样本；出现共同误判时改进证据合同，不通过反复全篇重写凑出一次通过

任何删减、延期或范围变化都要回到对应编号，写明理由、保留的原始要求和新的验收证据
