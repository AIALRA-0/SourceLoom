# 既有项目经验与源织的取舍

## 1 调查范围

本轮直接核对 ReadWeave、AEMP、模型转发器、Course OS、Workflow、Schedule 的代码或实施记录，并读取既有 Codex 用量调查

这是一份有来源范围的调查，不声称已经通读全部历史对话和所有仓库；精确本地证据索引保存在私有调查记录，公开文件不包含私人路径、主机或账号数据

## 2 设计风格

- AEMP 使用深色文字、暖白背景、细分隔线和系统字体，主操作在前，原始事件按需展开
- AEMP 的体验报告要求先回答正在发生什么、原因、已证实与未知内容，不能用节点数量和日志墙当首页
- ReadWeave 的回答顺序根据问题类型确定，定义、比较、计算、步骤和边界分别组织，窄问题不会被强制展开成百科
- Course OS 将原始教学视觉和解释区分开，正式版本和合成数据分开，不能把私有课堂材料带到公开仓库

源织采用黑白灰工作台、材料优先、下一步明确和细节渐进展开，正文继续遵循独立写作技能

## 3 真实教训

- 历史用量调查记录了子任务树扩张、普遍高推理档、超长上下文和大工具结果共同放大消耗；因此源织限制调用数量和输入范围，不把所有角色历史不断累积到一个会话
- Workflow 的远程数据库验证曾被默认 5 秒超时中断，明确 60 秒远程预算后约 17 秒完成；因此本地和远程验证分别设期限，保留首次失败原因
- 模型转发器明确禁止在上游已提交或结果不确定时盲目换账号重发；因此源织保存原任务身份并查询恢复
- 模型转发器明确指出服务健康不能证明当前模型可用，输出长度字段也不能作为上游硬上限；因此真实试验以具体任务回执为准
- ReadWeave 导入会清理正文、调整标题并重写资源链接；因此压缩包验证不能代替编辑保存后的读回
- Workflow 记录过备份目录缺失及发布包缺少脚本，进程未开始不能被诊断成程序本身失败；因此源织检查当前产物和错误位置，不继承历史根因
- Course OS 已经有播放器、测验和长期掌握记录；因此源织聚焦论文和混合文稿加工，复用服务对接经验，不扩展新的播放器
- Schedule 的更新记录保留取消任务的原文，并对并发领取加入预算边界；因此源织取消和暂停保留已完成材料，费用预留使用事务

## 4 复用与许可

- ReadWeave 作为独立服务，通过公开结构和接口适配，不复制其受不同许可证约束的内部实现
- 模型转发器复用任务与额度服务，不复制登录状态，不扩展账户管理
- 写作技能使用运行时引用并记录版本，公开项目提供其来源入口，不维护第二套规则
- Course OS 提供设计和故障经验，课程数据、截图与私人材料不迁入源织

## 5 核对入口

真实材料补充验证暴露了另一类问题：代码引用语法未展开会产生空代码块，一次请求生成多个章节可能只返回前几个章节，模型的正常结束标记不等于完整覆盖，长审核也可能消耗全部额度而没有正文

后续生成要按已核对的输入清单保留单节产物，缺节只补缺节；最终交付必须给原文与实际成稿，程序检查数量不能替代用户看到的输出，详见 [真实案例](REAL_CASES.md)
