# SourceLoom 主动编排实施记录

## 1 具体变化

新任务先确定改写边界、全部源信息、理解依赖和文章结构，然后按相邻章节分批写作；短文不会因为规划出了许多小节，就为每个小节单独调用模型

前后衔接使用前面已经保存的最终正文，不能把规划中打算解释的内容当成读者已经读过的内容

原始图片、表格、代码、公式和链接由程序按原对象身份插入，模型负责说明含义与安排位置，不能靠重新抄写对象来保证完整

正文出现问题后，模型只提交明确位置的字符补丁；程序确认旧文字、正文版本、允许修改的段落和原对象都吻合后，才一次性保存修改，未命中的正文保持不变

实施中保留了当前写作批次的一次独立上下文核对，因为真实输入确实暴露了人称变化、时间限定遗漏和术语提前使用等问题；后续只核对本次修复及其直接影响，不安排多个角色反复审查整篇文章

## 2 工作流与原始计划

完整流程保存在 [实际工作流](ACTIVE_COMPOSITION_WORKFLOW.mmd)，原始设计及两个项目的借鉴依据保存在 [架构分析](ACTIVE_COMPOSITION_ARCHITECTURE.md)

四份规划产物可以在同一次请求中生成，它们是四类需要明确的信息，不意味着固定增加四次模型调用

写作批次与文章章节分别记录；正文保留章节层级，执行时把相邻章节合在一次请求内，让模型看到本段与下一段的关系

原件中的每个片段都必须分配到规划中，未分配的尾段不能被静默丢弃；这种核对能发现编号和字符范围遗漏，不能单独证明模型已经理解全部语义

## 3 必须保留的约束

- 普通改写保留原文主旨、作者人称、指代、条件、数字、否定和不确定性，不自行增加教学情境、练习或组织政策
- 完整写作技能随每次模型请求原样交付，技能文件和角色提示词均保存版本摘要；摘要证明版本和交付内容，不能证明模型百分之百执行
- 查证需要读取实际来源，搜索摘要只能帮助找到资料，不能代替支持结论的原页面
- 图片读取结果保留与原图的对应关系，模糊或裁切的信息保留具体限制，不臆造不可见文字
- 原件与资源按实际字节校验，来源引文由程序从已保存材料取得，不采用模型重抄的引文充当准确证据
- 每个完成的批次保存正文版本、实际知识增量和检查记录，恢复任务时复用已经返回的结果
- 网络送达未知与明确失败分别保存，未知请求不能自动重发，旧版本和费用记录不能清零
- 旧任务保持原执行方式，新流程失败不会偷偷回退到旧的整篇审查

## 4 修订与成本边界

每个写作批次最多接受四轮有明确位置的内容补丁，格式补丁最多两轮，达到上限仍有问题时保留结果和原因；这些上限用于阻止无界循环，不表示订阅账户额度耗尽，也不设置整篇测试的 180 分钟时限

模型调用优先使用配置好的深度求索订阅通道，只有供应方明确返回订阅额度不足时，才按既有配置使用官方付费通道；所有试验和失败记录继续累计

按量费用使用配置中的人民币单价，历史外币记录保留原币种，订阅费用不伪装成按量价格；记录中的零新增按量支出不意味着订阅本身免费

同一资源保留多个来源地址但不重复放入相同正文，已经得到的规划、查证和成稿可继续读取；成本优化不靠压缩固定字数或删除源信息实现

## 5 页面与后台

上传保存后关闭页面不会取消任务，页面显示真实处理阶段和已完成批次，不把调用次数换算成虚假的剩余时间

进度读取使用小型状态记录，正文按实际版本缓存，进度更新不重新载入阅读页面；工具栏统一整理编辑、下载、导入、版本和材料管理入口

图片默认折叠，可以单张打开，也可以用总开关一起展开或折叠，原文与改写两侧共用开关，状态按材料保存

点击关联正文可以定位并轻度高亮原文，点击原文也能返回关联正文；多个来源分别保留可选关联，不把整页来源假装成某一句的准确定位

## 6 验证方式

真实素材采用 Git 的安全报告说明、滑铁卢大学的旅行商问题网页和一篇四页公开论文，分别检查短文条件与人称、网页图片与旧版布局、论文页面与长文连续性

生成与修订由模型经过实际处理流程完成，不由开发者逐段代写最终正文；失败稿、修复请求和费用记录保留在私人运行记录中

程序测试验证来源身份、对象保留、精确补丁、后台恢复、费用保护和导出结构，浏览器检查图片开关、双向定位和阅读期间的刷新行为

当前批次的模型核对、整篇独立语义验证和用户接受分别记录；结构检查通过不等于形式化证明原意完全无损，模型未发现问题也不能代替用户阅读

最终真实案例的状态、请求次数、页面检查和导出结果在交付前追加，正在运行的任务不能记成完成
